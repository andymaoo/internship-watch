# September 29 source contract repairs

## Verified defects and evidence

Production revision `ce0d1ccc882b` was healthy at the service level but its four
latest completed polls were degraded. Atlassian had failed 59 consecutive polls
because requisition 27067 used the new public
`globalmobility-careers-atlassian.icims.com` portal. Capital Group and Fidelity
Workday searches exposed incomplete upstream rows containing no title or public
posting path. The latest worker and supervisor outboxes had no pending delivery.
The validation queue had fallen to 26 due records. Daily local restore evidence
was current; automatic off-host storage remains unconfigured.

The repair adds the exact Atlassian portal host while retaining requisition and
path checks. During the complete staged audit, Atlassian also returned one
requisition mirrored across two already approved regional portals. The adapter
merges only records whose complete non-portal content is identical, validates
every portal URL, and selects a deterministic destination; a title, location,
description, identity or other core difference still fails. A Capital Group row
with an exact public posting path is ignored
only when that same Workday detail endpoint proves HTTP 404 or 410; redirects,
access failures and other statuses still fail the source. Fidelity consistently
returned eight search-only shells containing only a requisition identifier. The
adapter now collects its 331 usable records, exposes the eight unresolved shells
as `source_partial_records` telemetry, and creates a separate maintenance
warning. It does not create jobs from shells or label them open or closed. An
all-shell response and any broader malformed shape still fail collection.
